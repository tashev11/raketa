# Масштабируемый каталог «Ракеты»

## Цель

Поддерживать десятки и сотни тысяч поисковых вариантов документов без копирования юридического текста и без раздувания `index.html`.

Формула каталога:

**базовый проверенный документ × ниша × услуга × сценарий сторон**

Пример:

- Договор оказания услуг
- Стоматология
- SEO-продвижение
- ИП → ООО

= `Договор оказания услуг — SEO-продвижение для стоматологии · ИП → ООО`

Юридическое тело наследуется от базового шаблона. Отраслевой вариант добавляет название ниши, конкретную услугу, поисковые теги, сценарий сторон, отраслевой контекст и автоматически заполняемый предмет документа.

## Архитектура

### `catalog-runtime.js`

Базовый справочник ниш и услуг. Содержит крупные категории малого и среднего бизнеса: медицина, красота, HoReCa, авто, недвижимость, строительство, digital, профессиональные услуги, логистика, торговля, производство, образование, агро и другие.

### `catalog-extra.js`

Второй слой справочника. Расширяет каталог специализированными нишами и услугами: профильная медицина, автосервисные направления, строительные специальности, IT, финансы, HR, производство, логистика, retail, образование, facility management, энергетика, агро и профессиональные исполнители.

Справочники объединяются по `slug`, дубликаты не добавляются.

### `catalog-virtual.js`

Главное отличие от старой схемы: десятки тысяч вариантов **не создаются как массив объектов при загрузке страницы**.

В памяти остаются:

- базовые документы;
- список ниш;
- список услуг;
- список допустимых пар `ниша ↔ услуга`;
- 4 сценария сторон.

Конкретный отраслевой объект создаётся только:

1. когда он попал в результаты поиска;
2. когда пользователь открыл URL с его ID;
3. когда нужно заполнить, сохранить или скачать документ.

Это позволяет увеличивать каталог без пропорционального роста DOM и основного массива `templateCatalog()`.

### `catalog-policy.js`

Отраслевые результаты не должны вытеснять обычные инструменты.

Поэтому массовый каталог включается только когда запрос содержит контекст ниши или конкретной услуги.

Примеры запросов, которые включают отраслевой поиск:

- `SEO стоматология`;
- `CRM автосалон`;
- `поставка продуктов ресторан`;
- `1С производство`;
- `аренда звука мероприятие`.

Общие запросы вроде `НДС`, `договор`, `счёт`, `акт` остаются в базовом поиске портала.

### `catalog.html`

Отдельный пользовательский каталог-конструктор:

1. выбрать нишу;
2. выбрать подходящую услугу или работу;
3. выбрать тип документа;
4. выбрать стороны;
5. открыть готовый отраслевой вариант в основном портале.

На странице также можно просматривать все ниши и услуги через поиск и фильтры.

### `catalog-smoke-test.js`

Локальный smoke-тест структуры. Проверяет:

- что каталог содержит большой объём вариантов;
- что виртуальные варианты не раздувают `templateCatalog()`;
- поиск `SEO стоматология`;
- сохранение отраслевого контекста;
- автоматическое заполнение предмета;
- отсутствие отраслевого спама по запросу `НДС`;
- профильный договор аренды оборудования;
- расширенные запросы вроде `1С производство`.

GitHub Actions для этого теста отключён: на текущем аккаунте job завершался до назначения runner, из-за чего GitHub отправлял ошибочные уведомления о каждом коммите. Сам тест оставлен для локального запуска командой:

```bash
node catalog-smoke-test.js
```

## Сценарии сторон

Первый этап ориентирован на B2B:

- ИП → ООО
- ООО → ИП
- ООО → ООО
- ИП → ИП

Самозанятые, физлица и B2C должны добавляться отдельным слоем, потому что для них нужны другие юридические правила и оговорки.

## Правило качества

Нельзя считать карточку новым юридическим шаблоном только потому, что изменилось название отрасли.

В интерфейсе корректнее использовать формулировки:

**«шаблоны и отраслевые варианты документов»**

и отдельно показывать количество базовых юридических основ.

По мере развития для самых популярных комбинаций нужно создавать действительно уникальные отраслевые тексты: предмет, этапы, результат, порядок приёмки, специфические риски и приложения.

## SEO

Нельзя автоматически создавать sitemap из всех возможных комбинаций.

В индексируемую SEO-страницу вариант переводится только после того, как у него есть достаточная самостоятельная ценность:

- уникальный интент;
- уникальный заголовок и описание;
- отраслевой предмет договора;
- конкретный порядок работ или услуг;
- необходимые данные и документы;
- отраслевые риски;
- дополнительные условия;
- FAQ;
- полезные связанные документы.

Остальные варианты остаются доступны через внутренний каталог и поиск, но не обязаны индексироваться поисковиками.

## Следующие этапы

1. Вынести 83 базовых документа из монолитного `index.html` в отдельные данные.
2. Создать отдельные отраслевые поля и условия для самых популярных 100–300 услуг.
3. Добавить самозанятых и отдельные B2C-сценарии.
4. Добавить категории и хлебные крошки в `catalog.html`.
5. Сделать SEO-генератор только для отобранных качественных страниц.
6. Добавить sitemap для одобренных страниц.
7. Развивать справочник в сторону 300–500 ниш и 2 000–5 000 реальных услуг без изменения основной архитектуры.
